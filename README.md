# vision-inspection

环形轴承防错视觉检测系统。基于 OpenCV + PySide6，支持海康工业相机（MV-CA050-10GC）接入、自动拍照检测、照片流程演示（纯照片验证）。当前版本 **1.0.7**。

## 判定逻辑（事件驱动，不用时间窗口）

三态状态机，对应三个工位状态：

| 状态 | 画面 | 判定 | 状态机 |
|---|---|---|---|
| 检测到轴 | 无环、无工件A（主轴露出） | 环 ABSENT | `IDLE` 安装结束/待机（合并态） |
| 检测到轴承 | 有环、无工件A | 环 PLACED，锁存 | `RING_READY` 放置轴承 |
| 检测到工件A | 工件A到位遮挡环 | A 到位（环被挡，判 UNCERTAIN 属正常） | 回到 `IDLE` 安装结束/待机，本件 OK |

异常（进 FAULT/漏装，需人工复位）：
- 无轴承态出现工件A（A先于轴承，漏放环）
- 环在 A 到位前被取走

**判定方法：裁剪模板法（`ring_mode=crop_template`）**。旧的"径向暗谷 + 霍夫找圆心"方案已弃用——霍夫在整图上会找到几百个候选圆，取"离中心最近"常落在螺栓孔上，导致暗谷量到外圈阴影、判错状态。新方案：

每帧处理链：原图等比缩放到 1200px → 以训练标定的环心为中心裁一块固定小图（默认半径 130px）→ 该小图分别与"有环 / 无环 / 工件A"三类示教模板做 NCC 匹配 → 取最高分类别 → 连续帧去抖（环 3 帧 / A 2 帧）→ 状态机。相机固定后环心不变，默认直接用固定环心（`use_locator=false`，最稳）；如相机可能轻微偏移，可开 `use_locator=true` 在环心附近做局部微调搜索。

新三张现场图（1920×1440 竖版）实测 NCC 分离度：

| 输入 | 有环模板 | 无环模板 | A模板 | 判定 |
|---|---|---|---|---|
| 状态1 无环 | 0.46 | **1.00** | 0.00 | ABSENT |
| 状态2 有环 | **1.00** | 0.42 | 0.00 | PLACED |
| 状态3 放A | 0.00 | 0.00 | **1.00** | A 到位 |

## 相机自动拍照检测（检测页，v1.0.6）

检测页的「自动拍照检测」分组：连接相机（或文件图源）后点「启动自动拍照」，程序按固定间隔定时拍照并顺序判定，驱动一个独立的轻量状态机（`vision_app/auto_flow.py`，与 GUI 解耦、可无界面自测）。拍照间隔等参数在 **参数设置页 → 自动拍照** 分组配置：

| 步骤 | 触发条件 | 界面显示 |
|---|---|---|
| 安装结束/待机 | 启动时 / 检测到工件A之后；未检到轴、重复检到A均自保持（无超时） | **安装结束/待机** |
| 检测到轴 | 检出有主轴、无轴承（上一件已取走） | **无轴承** |
| 放置轴承 | 下一张有效照片检出轴承 | **放置轴承** |
| 本件完成 | 检测到工件A → 回到安装结束/待机，闭环继续 | **安装结束/待机** |
| 漏装（报警） | 无轴承态出现工件A / 环在A到位前消失 / 流程中超时拿不到有效照片 | **漏装**（蜂鸣+闪烁，需复位） |

**主轴判据**：环心裁剪小图的中央 35% 子区与"轴模板"做 NCC，≥`shaft_ncc_th`（默认 0.60）判有主轴。现场实测：状态1=1.00、状态2≈0.00、状态3≈-0.18。轴模板在训练时自动从无环（状态1）样本中心区生成；旧模型没有 shaft 模板时运行时自动从 absent 模板派生，无需重训。

**有效照片的定义与异常处理**：取帧成功且检测成功才算有效照片。拍照失败（取帧为空/超时/异常）、检测失败（管线异常、环状态 UNCERTAIN 且未检出工件A 且勾选"高置信"）都不计有效照片，只累计失败次数并继续重拍；连续 `max_invalid_retries`（默认 3）次失败、或等待下一张有效照片超过 `photo_timeout_ms`（默认 3000ms），都判漏装并报警。报警为锁存状态，人工点「复位」后才能重新开始；本件完成后检测到轴会自动开启新周期。待机中未拍到裸轴、直接检出轴承时给出顺序提示并按「放置轴承」继续，不误报。

**可配置项**（`config.json` 的 `auto_flow` 段，参数设置页可改并"保存到 config.json"）：

| 参数 | 含义 | 默认 |
|---|---|---|
| `interval_ms` | 拍照间隔 | `1000`（每秒一张） |
| `photo_timeout_ms` | 等待下一张有效照片的超时 | `3000` |
| `max_invalid_retries` | 连续拍照/检测失败上限 | `3` |
| `require_shaft` | 启动是否要求同时检出主轴 | `true` |
| `require_confident` | UNCERTAIN（且未检出A）是否视为检测失败 | `true` |
| `bearing_confirm` | 已废弃（完成依据改为检测到工件A），保留仅为兼容旧配置 | `2` |
| `alarm_enabled` / `save_captures` | 报警开关 / 保存自动照片到 captures/auto | `true` |

每张有效照片、每次失败与超时都写入检测页的「自动拍照检测」记录表（含流程节点列）与日志，可导出 CSV。无界面自测：`python selftest_auto_flow.py`（状态机全分支 + 三张现场图端到端）、`python selftest_auto_gui.py`（离屏 GUI 用文件图源跑完整周期）。

## 照片流程演示（流程演示页签）

用于验证判定逻辑：选一个照片文件夹，程序按文件名顺序逐张读取、判定每张属于哪个流程节点并显示，核对判定是否有错。**与相机无关，纯照片验证。**

**工作原理**：把来源照片以 `001_/002_...` 序号前缀复制进可配置的目标文件夹（保证顺序、可重复）→ 逐张送进现有检测管线 + 事件驱动状态机 → 记录每张的自动判定、流程节点、状态机前后状态与事件、评分、进度 → 可导出 CSV 报告 → 重置后原样重跑。

**来源目录容错**（v1.0.4）：普通目录只取顶层照片（子文件夹不混入顺序）；若 `dataset` 三个标准子目录存在但为空、或顶层无图，会回退扫描整个根目录；若来源目录确实没有照片而目标文件夹里已有照片，则直接使用目标文件夹中的照片（按文件名排序，不复制不删除）。

**流程节点轨迹**（v1.0.6）：记录表新增「流程节点」列，把每张照片映射到业务节点，便于核对判断流程是否正确。预期节点链：**安装结束/待机 →（检测到轴）无轴承 →（检测到轴承）放置轴承 →（检测到工件A）安装结束/待机**；异常照片显示 **报警：…**（漏放轴承 / 轴承被取走 / 照片读取失败）并以红色标出。照片序列上方横幅随判定结果高亮 安装结束/待机 / 无轴承 / 放置轴承 / 漏装 四节点。

**可配置项**（`config.json` 的 `demo_flow` 段，界面也能改并"保存配置"）：

| 参数 | 含义 | 默认 |
|---|---|---|
| `source_dir` | 示例照片来源目录；普通目录按文件名自然排序，数据集根目录按 状态1→2→3 排序 | `dataset` |
| `target_dir` | 目标文件夹，照片按顺序复制进去 | `demo_flow_inbox` |
| `auto_pass_states` | 自动判定视为"通过"的状态机状态（本件完成以 CYCLE_OK 事件为准） | `[]` |
| `interval_ms` | 自动播放间隔（毫秒） | `1500` |
| `loop` | 播放到末尾是否从头循环 | `false` |
| `copy_to_target` / `clear_target` | 是否复制到目标文件夹 / 准备时是否先清空（保证可重复） | `true` |

**判定只看自动结果**（v1.0.7）：人工"通过/不通过"按钮与判断规则已移除，演示页只展示程序自己的判定轨迹（是否准确、合乎逻辑）。单张"检测到轴/检测到轴承"照片显示"未判定"（一个完整周期要以检测到工件A结束），只有 CYCLE_OK（本件完成）才是自动通过；这正是防错逻辑。判到漏装后**自动复位**（模拟实际操作：报警 → 复位 → 后续照片从头判定）。

**视觉展示**（v1.0.7）：照片上叠加环/A 状态彩框（含 NCC 分数）、**霍夫圆检测虚线圆**（紫，含圆心坐标与半径文字标注）、右上角 ✓通过/✗漏装/…未判定 判定印章；横幅四节点带图标与呼吸高亮动画；记录表整行按结果着色；照片序列列表带 ✓/✗ 标记与通过/不通过统计。

**操作**：流程演示页 → 选照片目录 → "准备照片" → "下一张（判定）"逐张推进（或"自动播放"）→ 表格实时显示判定出的流程节点与状态变化 → "导出报告 CSV"。可点序列或表格回看已处理的张；"重置重跑"清空记录从头来。（相机自动拍照在检测页，见上节。）

无界面自测：`python selftest_flow.py [来源目录]`（验证准备/判定/人工/重算/导出/重置重跑）。

## 运行

```bash
pip install opencv-python numpy PySide6
python ring_inspector_v2.py              # 正常启动
python ring_inspector_v2.py --selftest   # 无相机自检（5 秒后写 selftest_v2.png/txt）
python train_model.py --init-config config.json
python simulate_1_2_3.py                 # 用三张状态图跑端到端模拟
```

## 标注图说明

裁剪模板法的标注很干净：黄色方框=裁剪区（固定套住环）、绿色点=环心。不再有旧方案的满屏红圈（霍夫候选）、蓝/黄暗谷亮峰圈。状态3环被工件A遮挡时环判为 UNCERTAIN 属正常，此时由 A 模板判定周期结束。

## 重新训练

把同视野拍的三张状态图放到任意目录（如 `captures/`），按顺序执行：

```bash
# 自动定位环心
python train_model.py --state1 captures/1.jpg --state2 captures/2.jpg --state3 captures/3.jpg --config config.json
# 手工指定环心（归一化 x,y，相机固定后推荐，最稳）
python train_model.py --state1 captures/1.jpg --state2 captures/2.jpg --state3 captures/3.jpg --ring-center 0.5069 0.4896 --crop-half 130 --config config.json
python stability_test.py captures   # 可选：光照/平移扰动下的稳定性自测
```
